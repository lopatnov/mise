# Внутренняя документация для Claude

Это внутренняя память дирижёра (не документация продукта — та в README/CHANGELOG, зона
`technical-writer`). Обновляется дирижёром напрямую по мере необходимости, отдельной роли для
этого нет.

## Карта `.claude/` (для дирижёра)

```text
.claude/
```

Нет папки `backlog/` — продуктовый бэклог, баги и находки обоих радаров живут в GitHub Issues
проекта (`lopatnov/mise/issues`): `tech-radar` — устаревшие технологические решения самого
проекта (`/maintain`), `idea-radar` — идеи, подсмотренные у аналогичных проектов (`/evolve`).
Локальные файлы для этого не заводим: одно место правды, видимое пользователю без захода в
репозиторий.

## Порядок чтения при старте сессии

`CLAUDE.md` → `rules/index.md` → `rules/workflow.md` → `rules/team.md`. Дальше — профильные
файлы агентов по мере вызова ролей; перед первым запуском `/evolve` — дополнительно
`skills/group-chat/SKILL.md`.

## Почему два цикла и два паттерна, а не один

`/maintain` унаследован по образцу другого проекта того же пользователя (`pressmark`) —
процедурная поддержка (зависимости/security/рефакторинг) там уже показала себя как рабочий
чек-лист на orchestrator-worker, без нужды это менять. `/evolve` — новое: у Mise, в отличие от
`pressmark`, есть прямой смысл систематически изучать множество аналогичных open-source проектов
(recipe/kitchen management — конкурентная ниша с несколькими зрелыми альтернативами) и осознанно
заимствовать идеи, а не изобретать фичи в вакууме. Для этого выбран паттерн **Group Chat**
(несколько персон реально видят реплики друг друга и спорят), а не ещё один orchestrator-worker
проход — потому что ценность здесь именно в столкновении точек зрения (research vs осуществимость
vs скепсис vs продуктовый fit), а не в последовательном сборе независимых мнений. Оба цикла — раз
в две недели, сдвинуты на неделю друг относительно друга, чтобы проект получал внимание примерно
раз в неделю, попеременно update/develop, без взаимного наложения PR/issue-потока.

## Почему 13 ролей, а не меньше/больше

Десять ролей ядра — тот же принцип, что в `pressmark`: роль оставлена только там, где регулярно
нужна реальная экспертиза, изоляция шумного вывода, или достаточно крупная автономная подзадача,
адаптированная под стек Mise (NestJS/Mongoose вместо .NET/gRPC, npm для обеих частей вместо
NuGet+npm, Biome вместо `dotnet format`+ESLint+Prettier). Три роли `/evolve` — не «на будущее», а
прямое следствие выбора Group Chat: паттерну нужны минимум research-голос, техническая
осуществимость и осознанно оппонирующий голос, иначе «обсуждение» вырождается в один доклад без
трения. Новая роль допустима только когда одной из существующих зон реально не хватает — не
заранее.
